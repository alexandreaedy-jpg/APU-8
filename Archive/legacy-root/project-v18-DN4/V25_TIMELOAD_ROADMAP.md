# APU-8 V2.5 Time Load Roadmap

## Purpose

Estimate the real time and workload involved if `APU-8 V2.5` becomes a Kickstarter-backed commercial product.

This roadmap is not a firmware roadmap.

It is a **life-load roadmap**:

- how much work
- at what stage
- and where the project starts to behave like a real small hardware business

## Big Picture

If the product is successful, this is not a "weekend side task".

It is more like:

- a serious long-term side project at first
- then a temporary second job
- and during some phases, close to a full-time commitment

That does **not** mean it is impossible.

It means the project must be handled in phases, with deliberate go / no-go checkpoints.

## Phase 1 - Technical Validation

### Goal

Prove that the architecture is musically strong enough to deserve productization.

### Typical work

- transport/protocol stabilization
- ROM/runtime stabilization
- control layout decisions
- noise / modulation / voice testing
- live musical testing
- hardware iteration

### Time range

- **`2 to 6 months`**

### Weekly load

- **`5 to 15 h/week`**

### Notes

This is still a development phase.

The work is heavy, but mostly creative and technical.

This phase is the least "business-like".

## Phase 2 - Prototype That Matches the Future Product

### Goal

Build a prototype convincing enough for:

- demos
- musician testing
- manufacturing discussion
- Kickstarter preparation

### Typical work

- convert proto into product-like architecture
- industrially plausible wiring/PCB choices
- enclosure concept
- connector concept
- front-panel control layout
- visual identity direction
- first documentation cleanup

### Time range

- **`2 to 4 months`**

### Weekly load

- **`8 to 20 h/week`**

### Cost range

- **`5k to 15k €`** for a credible but still pragmatic campaign prototype
- **`15k to 30k €`** if the prototype becomes very close to production reality

### Notes

This is often the first phase where the project starts to cost real money, not just time.

## Phase 3 - Kickstarter Preparation

### Goal

Prepare a campaign that is honest, attractive, and manufacturable.

### Typical work

- budgeting
- BOM cleanup
- manufacturer outreach
- campaign page writing
- video and demo production
- product photography
- reward tier design
- FAQ / shipping assumptions
- legal/accounting prep

### Time range

- **`1 to 3 months`**

### Weekly load

- **`10 to 25 h/week`**

### Notes

This phase can feel deceptively "non-technical", but it is still very demanding.

Bad work here can destroy a technically good product.

## Phase 4 - Kickstarter Campaign Live

### Goal

Run the campaign and keep community trust high.

### Typical work

- daily communication
- answering questions
- posting updates
- social/community outreach
- handling press/influencers if any
- correcting misunderstandings quickly

### Time range

- typically **`30 days`**

### Weekly load

- **`15 to 35 h/week`**

### Notes

This is the first phase that can feel emotionally intense every day.

Even if it is "only one month", it can be exhausting.

## Phase 5 - Post-Campaign Engineering Lock

### Goal

Turn the promised product into a final build package for manufacturing.

### Typical work

- spec freeze
- final electronics changes
- DFM adjustments
- connector finalization
- enclosure finalization
- firmware production cleanup
- factory sample review
- test procedure definition

### Time range

- **`1 to 3 months`**

### Weekly load

- **`15 to 30 h/week`**

### Notes

This phase is dangerous because many creators think the hard part is over.

In reality, this is where the project becomes industrial and unforgiving.

## Phase 6 - Production and QA

### Goal

Get the product actually manufactured without losing control of quality.

### Typical work

- supplier follow-up
- sample approval
- defect triage
- test runs
- packaging validation
- production scheduling
- cash monitoring
- QC rules

### Time range

- **`1 to 3 months`**

### Weekly load

- **`10 to 25 h/week`**

### Notes

The work becomes less creative and more operational.

This can be mentally tiring in a different way than development.

## Phase 7 - Fulfillment, Support, and Aftermath

### Goal

Deliver to backers and survive the first real-world support wave.

### Typical work

- address handling
- shipping coordination
- missing parcel issues
- damaged unit replacement
- basic support
- warranty-style incidents
- accounting/admin cleanup

### Time range

- **`2 to 4 months`**

### Weekly load

- **`8 to 20 h/week`**

### Notes

This is the phase many creators underestimate.

It is less glamorous than the campaign, but it can quietly consume a lot of time.

## Human Workload Summary

### Before Kickstarter

Combined development + productization + campaign prep:

- **`5 to 13 months`**
- often **`8 to 20 h/week`**, with peaks above that

### Campaign + first post-campaign stretch

From campaign launch through production lock:

- **`2 to 6 months`**
- often **`15 to 35 h/week`**

### Production + fulfillment stretch

- **`3 to 7 months`**
- often **`10 to 25 h/week`**

## Realistic Personal Interpretation

### Best case

You keep this as a very serious side project.

- sustainable
- intense at times
- still compatible with normal life if paced well

### Middle case

During campaign and delivery windows, the project becomes a **second job**.

- evenings
- weekends
- regular stress
- lots of context switching

### Heavy case

If the campaign overperforms or if manufacturing gets messy, it can feel temporarily close to a **full-time responsibility**.

That is not because the product is too big.

It is because hardware launches multiply small obligations.

## Most Dangerous Time Traps

- underestimating prototype-to-product work
- underestimating connector/mechanical iteration
- handling all support personally
- not preparing fulfillment early enough
- adding too many features before launch
- trying to make the first version too premium

## Best Strategy To Keep It Humanly Manageable

### Keep V2.5 narrow

The first commercial version should prioritize:

- musical strength
- reliable timing
- solid controls
- good enclosure
- no feature creep

### Delay luxury features

Examples to delay if they are not already solid:

- LCD / OLED
- extra modes
- too many advanced UI layers
- complex visual flourishes

### Build decision checkpoints

Do not commit emotionally to the full product path too early.

Use checkpoints:

1. technical proof
2. product-like prototype
3. costable manufacturing path
4. Kickstarter readiness

## Final Reading

Yes:

- it can become a lot of daily work
- the prototype before Kickstarter can cost real money
- and a successful campaign creates responsibility, not relief

But it is still feasible if treated as:

- a staged boutique hardware launch
- with strict scope control
- and honest recognition that some phases will feel like a second job

## Practical Conclusion

If you ever decide to commercialize `APU-8`:

- expect **many months of serious work before Kickstarter**
- expect **a very demanding 6 to 12 month window** around campaign + production + fulfillment
- and expect that the first release must be **narrow, stable, and manufacturable**, not maximal

That is the version of this project that has the best chance of actually shipping.
